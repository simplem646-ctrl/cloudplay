# T9b brief: menus, sleep summary, save/load UI, settings, ending, credits

## Context
- Task #20 in the plan run by the orchestrator. Game: "Bellhaven Days" (Harvest-Moon-Back-to-Nature-style school life sim, Three.js, frontend-only). You build the out-of-world screens as SCENES that other code opens through `src/scenes/registry.js` (read its header: scene names, params and results are the contract). You never import other scene tasks; T9a (overworld/stage/title) and T8a/T8b (academics, activities) are built in parallel.
- READ FIRST: `docs/game/00_OVERVIEW.md`, `docs/game/01_RENDER_ART_UI_CONTRACTS.md` sections 1, 6, 8, `docs/game/02_SIM_CONTENT_CONTRACTS.md` (all; sections 3-6, 10, 11, 13 are yours), `docs/game/api/engine.md` (Scene, SceneManager, input), `docs/game/api/ui.md` (widgets), `docs/game/api/art.md` (portraits/icons/title/ending backdrops), `docs/game/api/audio.md`, `docs/game/api/sim.md` + `events.md` (state, save, calendar, relationships, inventory, endings composer), `src/sim/state.js`, `src/data/{calendar,cast,items,ids}.js`, `src/core/constants.js`.
- Style: reuse the UI toolkit; parchment panels for status/records, navy panels for menus; consistent cursor/sfx behaviour; everything keyboard/gamepad/touch operable; confirm/cancel semantics as in the input contract.

## Required deliverables (scenes registered with `registerScene` in `src/scenes/menus/index.js`, which exports `registerMenuScenes()`; T9a's boot calls it)
1. `pause` (opens from the overworld with Esc/Menu; tabbed): `status` (name, date, energy, money, six subjects + three traits as bars, conduct, club + rank, job, standing/average, community spirit, partner/hearts summary), `items` (grid with descriptions; Use for food/study items via `sim.inventory.use`, Give is NOT here), `friends` (list of met characters with portrait, hearts row (0-10), birthday, short bio line, romance status; sorted: partner, romance options, friends, others), `journal` (quests: active/complete with notes from `state.quests` + quest definitions from the registry; the main goals first), `calendar` (CalendarGrid for the current season with festivals, exams, breaks, birthdays; select a day for details; next/prev season within the year), `records` (exam results table per exam, report cards, attendance counts, endings seen from the meta save), plus `save` and `settings` and `title` (confirm). Each tab may also be opened directly through its own scene name: 'status','items','friends','journal','calendar','records'.
2. `sleep` (day summary; params `{summary}` from `sim.clock.sleep`): "Day N" card, what happened today (money change, hearts gained per NPC (portrait + hearts), subjects improved, events seen, weather tomorrow, festival/exam notices for tomorrow), a pleasant night transition (moon/stars pixel animation, soft music), then the new-day banner ("Spring 14 - Sunday - Sunny"); returns `{}`.
3. `save_menu` / `load_menu`: 3 manual slots + `auto` slot (read-only in save menu) with summaries (date/time, location, play time, partner, a mini portrait of Theo), overwrite confirm, load confirm, delete; uses `sim.save` (graceful when storage is unavailable: show a notice and keep playing).
4. `settings`: master/music/sfx volumes (applied live through `audio.setVolume`, saved via `sim.save.settings`), text speed (slow/normal/fast, stored in settings and honoured by DialogueBox via a shared `game.settings`), show/hide key hints, "reset all data" with double confirm; reachable from the title and the pause menu.
5. `ending`: takes `sim.endings.composeEnding(state)` slides, plays them with art backdrops (`getEndingBackdrop(slide.art)` or the title backdrop fallback, season-tinted), typewriter text, music per slide mood (`ending_good` / `ending_bittersweet`), skip with confirm; records the ending in the meta save; then pushes `credits`. 
6. `credits`: scrolling credits (Bellhaven Days; "Created with Claude"; sections for design, art, music, writing, engineering, thanks to the player; original creation notice: no assets from other games), a stats screen (days played, exams passed, mini-game wins, hearts, partner), then returns to the title.
7. Tests for pure logic (`test/scenes/menus_*.test.mjs`): friends sorting, calendar data building (festival/exam/break/birthday markers per season), summary-diff computation for the sleep card, save-slot summary formatting, ending slide selection wiring with fake state. Scenes themselves get a dev harness `src/dev/menus_demo.js` with mock game services (`?scene=pause|sleep|save|settings|ending|credits|status|friends|journal|calendar|records|items`) for screenshots.
8. `docs/game/api/menus.md` (<= 200 lines): scene names/params/results, data each screen reads, how to extend.
