- Task #19 in the plan run by the orchestrator. Game: "Bellhaven Days" (3 school years of a Harvest-Moon-Back-to-Nature-style school life sim; Three.js; frontend-only). You INTEGRATE the building blocks that other workers built into a playable game loop. This is the most important integration task: the game must feel good to walk around in.
- Already integrated and documented (READ ALL of these API docs first): `docs/game/api/engine.md` (renderer, WorldView, Actor, camera, mover, A*, input, scenes, weather, grading), `docs/game/api/ui.md` (DialogueBox, ChoiceBox, HUD, ListMenu, Toast...), `docs/game/api/world.md` (maps, tileset, anchors), `docs/game/api/art.md` (sheets, portraits, icons, title art), `docs/game/api/audio.md` (audio singleton; `src/audio/index.js` exists), `docs/game/api/sim.md` + `docs/game/api/events.md` (clock, calendar, weather, relationships, inventory, shops, schedule, save, `createSim`, conditions, interpreter, events, dialogue, endings), `docs/game/api/story_main.md` (main story ids/flags). Also `docs/game/00_OVERVIEW.md`, `docs/game/01..04` and ESPECIALLY `docs/game/02_SIM_CONTENT_CONTRACTS.md` sections 7, 12, 13 and `src/scenes/registry.js` (lead-owned scene + director registry; read its header: the scene names, params and results are the contract between you, T8a, T8b and T9b).
- Other workers build IN PARALLEL with you and register their scenes through `src/scenes/registry.js`: T8a (class, exam, report_card, activity:study_*, school-day director), T8b (shop, activity:*, minigame:*), T9b (pause + submenus, sleep summary, save/load menus, settings, ending, credits). You do NOT implement those; you call them through `openScene`/`openCall` and provide FALLBACKS when a scene is not registered (log once, show a toast "Coming soon", continue). Some maps may not exist yet (maps are built in parallel by T4a/b/c): a warp to a missing map must not crash: show a friendly line ("The door is locked for now.") and stay put.
- LEAD-BUILT ENTRY POINTS you wire up: (1) `src/sim/events_system.js` -> `createEventSystem(sim)` is THE way to find/run events, pick dialogue, give gifts and compose endings (`docs/game/api/events.md` has a 'Using it from a scene' recipe and the table of WHEN to ask for each trigger); `MockStage` in `src/sim/mock_stage.js` is a complete reference of the Stage shape. Your `src/scenes/boot.js` must call each present `fn()` once at boot (try/catch each, log failures) BEFORE pushing `title`, so scenes built by other workers light up with no further wiring. (3) rules modules you call at the right moments: `src/sim/{clubs,jobs,activities}.js` and `docs/game/api/academics.md` (the school-day director decides class/exam/report-card/remedial; you only need to honour `runDirectors` and open what it returns).
- Content (events/dialogue/schedules/quests/endings) arrives through the registry-backed sim modules; tolerate missing pieces (fallback generic lines, NPC not scheduled = absent).

## Required deliverables
1. `src/main.js` (replace the stub): boot sequence: build the app via the engine, assemble `game = { renderer, world, input, ui, audio, art, sim, bus, scenes, debug }`, register scenes, push `title`; global error overlay (never a blank page); expose `window.__game`. `audio.init()` on the first user gesture ("Press Start").
2. Title scene (`src/scenes/title.js`): art title backdrop (season-varying, animated clouds/birds/petals using engine weather or simple sprites), logo, menu New Game / Continue (disabled when no save; loads the newest slot) / Options (opens `settings` via registry) with title music; new game creates state via `createNewGame`, shows the opening banner ("Bellhaven - Spring, Year 1"), places Theo at `home_theo:bed` at 06:30 and fires the `wake` trigger.
3. Overworld scene (`src/scenes/overworld.js`): loads maps by id (tileset per season; map swap with fade), spawns Theo + NPCs; free pixel movement with `moveActor`, walk/run, collision with solids and NPCs, camera follow; interaction: face + confirm on NPC or interactable; warps (step on warp rect -> fade -> `to` anchor; evaluate `requires` with the conditions module, show `lockedText`); footsteps by tile `meta.sound`; HUD (location banner on map change, clock, date, weather, money, energy) wired to state; in-game time advances at `SECONDS_PER_GAME_MINUTE` only when idle (not in dialogue/menus/scenes/scripts); day/night + season + weather presentation (engine grading presets by time, `lantern` lights at night near anchors/windows where reasonable, rain/snow/petal/leaf particles by weather and season, indoors = `indoor` grading and no weather); ambient music/ambience selection (`'town'`, `'school'`, `school_class` in lessons; ids per MUSIC_IDS) via `audio`.
4. NPC manager (`src/scenes/npc_manager.js`): per in-game minute, ask `sim.schedule` where every NPC (cast + extras) should be; spawn/despawn actors for the current map; when the next waypoint is in the same map NPCs WALK there with A* (arrive at the time given), across maps they appear/disappear at doors; idle NPCs face their anchor `dir`; talking NPCs turn to the player; extras get appearances via `art.appearanceFromSeed`; cats use animal sheets; seated poses where the anchor name starts with `seat_` (use the sit pose in the matching facing); NPC outfit slot by context (school hours = school, evening/weekend = casual, sports/beach etc. when the schedule point `activity` says so); keep actor count and per-minute work cheap.
5. Stage (`src/scenes/stage.js`): implement the whole Stage interface from doc 02 section 7 over the overworld (say/narrate/think via DialogueBox with portraits from art, choice via ChoiceBox, warp, place, hide, moveTo (A*), face, pose, emote, cam, fade, flash, lighting, sfx, music/musicResume, banner, wait, call via `openCall`, endGame via `openScene('ending')`, `resolveAnchor` supporting current-map names and `map:anchor`). Scripts start with input locked and end with control returned; `skippable` events can be skipped by holding `skip` (fast-forward with a visible indicator).
6. Interaction & dialogue flow: talk -> `findEvent({type:'talk'})` else `dialogue.pickTalk`/`pickRepeat` -> lines in the DialogueBox with the NPC's portrait and face; after a first conversation offer "Give a gift?" (ChoiceBox + inventory list) -> `dialogue.giftReaction` with portrait reactions + heart toast; birthday greeting; hearts shown as toast; mark `met`. Interactable actions (all of `INTERACT_ACTIONS`): `sleep` (confirm -> forced day flow: `sim.clock.sleep` -> open scene `sleep` with the summary (fallback: simple fade + toast) -> autosave -> `wake` trigger), `save` (open `save_menu`, fallback: quick save to slot 1), `study` (open `activity:study_home` / `activity:study_library`), `shop`, `text`, `event`, `activity`, `job`, `rest`, `collect`, `board` (UI list of upcoming festivals/exams/notices from the calendar), `calendar` (calendar widget), `door_locked`.
7. Triggers: call `findEvent` for enterMap, wake, sleep, interact, talk, a per-minute `clock` check and an `auto` check about once per second while idle; run via `runEvent` with the Stage; avoid event spam (one at a time, short cool-down), and re-check after each event ends.
8. Directors (`src/scenes/directors.js`): `forced_sleep` (clock reaches 02:00 -> collapse/sleep scene with Aunt Roz scolding line) and `energy_collapse` (energy 0 -> nurse/clinic recovery with a cost, or home), registered with `registerDirector`; the overworld calls `runDirectors` each in-game minute while idle and opens the returned scene with the clock paused.
9. Pause: Esc/menu opens scene `pause` (T9b) with a fallback tiny menu (Resume / Save / Title) when not registered.
10. Debug API per doc 02 section 12 on `window.__game.debug`: warp(map, anchor?), setTime('HH:MM'), setDate(y, season, day), giveMoney, giveItem, setFlag, addFriend, setStat, sleep(), skipDays(n), runEvent(id), listEvents(), state(), loadState(json), press(action, ms), screenshot(), plus `nextFrame()`/`waitIdle()` promises for scripted tests.
11. `src/dev/flow_*.js` harnesses if useful; tests for pure parts (NPC placement planning, trigger cool-downs, anchor resolution) in `test/scenes/flow_*.test.mjs`.
12. `docs/game/api/scenes.md` (<= 250 lines): how the game is assembled, the `game` object, how to add scenes/directors, how triggers/stage work, the debug API, known limits.
